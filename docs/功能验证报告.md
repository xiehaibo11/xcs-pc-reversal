## 三、关键结论：上一会话 fulltest 的 C2-C5"失败"全部是测试脚本假象

- 上一会话 4 轮真机测试 C2 开始/C3 结束/C4 重新开始/C5 重启设备 均报 "no dialog appeared"。
- 本次同功能在 fixture 上全部实弹通过（弹窗+请求双重证据）；
  重启设备、开始、结束的弹窗均被截图/弹窗读取器捕获。
- 根因：fulltest.ps1 的 `Find-Btn`+UIA InvokePattern 命中了错误/陈旧元素（本会话 computer-use
  的无障碍树也存在**裁剪**——顶栏按钮被裁掉不出现，但 raw UIA 树可见且坐标正确）。
  按钮本身零缺陷。
- 真实服务器侧亦无问题：python 直连探测 start/end/reset/restart 均 0.1s 返回 success:true。

## 四、真机验证抓到并修复的缺陷（fixture 侧）

1. **check_update 响应缺 `code` 键 → 客户端 KeyNotFoundException**
   `HttpReq.cs:38` 对一切 `success=false` 无条件读 `dictionary["code"]`（原版如此，
   真实服务器恒带 code）。fixture 初版 check_update 未带 → HomeViewModel 构造崩溃 →
   "登录异常错误"弹窗。已修复（补 code:0，对齐真实服务器形态）并在 selftest 加回归断言。
   **这反向证明还原代码忠实复刻了原版（连脆弱的错误处理都一致）。**
2. fixture 其余加固（子代理已做）：绑定 127.0.0.2（本机 Docker 占用 127.0.0.1:8081）、
   序列号必须数字（HomeViewModel.cs:3189 `int.Parse`）、图片 base64 规避 dataKey 替换字符、
   失败响应统一带 code。

## 七、原版 vs 还原版 同屏对照（2026-11-12 追加）

实验：原版 `PC端/原始包解压/xcs电脑图传/xcs.exe`（.NET Framework 4.7 原始二进制，隔离目录运行）与还原版
`PC端/测试副本/xcs-2015/xcs.exe`（net8.0-windows）在**同一 appsettings.ini**（SERVER=127.0.0.2
预填、同 VERIFY 口令）下各自启动过门禁，对比登录窗：

- UIA 元素树 **23/23 逐一相同**：同索引、同控件类型、同名称（用户名称/用户密码/口令地址/
  记住密码/立即登录/重置口令/客户端版本号：2.0.15）、同预填值；
- 皮肤像素级一致（哥特龙纹原版贴图，res/ 资源直出原包）；
- 此前怀疑的"SERVER 预填后口令地址栏仍显示"经对照确认为**原版固有行为**，非还原偏差；
- 结论：还原版 UI 是对原版的忠实重建（XAML 解码自原 BAML、资源直出原包、事件接线对照
  原始 Connect() 表），而非自行设计。
