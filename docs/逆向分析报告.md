## 二、① xcs电脑图传(新) — xcs.exe（2026-04 版，app_version 2.0.15）

**技术**：C#/.NET WPF + MVVMLight + websocket-sharp + Newtonsoft.Json + BouncyCastle + Microsoft.Extensions.Configuration.Ini
**反编译**：ILSpy 9.1 → 45 个 .cs 文件（`analysis/xcs-cs/`），接近原始源码质量

### 与安卓客户端逐项比对（全部一致）
| 项 | PC 版 | 安卓逆向 |
|---|---|---|
| 登录 | `POST http://{ip}:8081/api/login/login/distinguish?app_name=xcs` | 同 |
| 服务器配置 | `POST server/get_server_addr`（客户端生成 RSA-2048 公钥指数3 密钥对） | 同（PointyCastle） |
| WS | `ws://{ip}:18889/`（websocket-sharp） | 同（Rust tokio-tungstenite） |
| 协议常量 | types 1/2/3/4/5/6, 50/51/52/53/54, ERR 301 | 逐字相同 |
| 协议字段 | types/data_content/from/to/fp/qos/**retry_count** | 安卓 JSON 无 retry_count（PC 新增） |
| 图片URL | `http://{ip}/{url}` + dataKey 替换规则 `\|`分组`,`对换 | 同一条 decode_data |
| 401 处理 | success=false 且 code==401 → "当前登录已失效" | 同逻辑 |

### 关键文件
- `distinguish.Common/Constant.cs`：全部协议常量
- `Global.cs`：jwt/ipAddr/username/password/dataKey/rsaKey；`verifyDefaultPwd="E951081AC30FFA83F10B68CDE1CAC7"`（校验口令 MD5）
- `AppConfig.cs`：INI `./appsettings.ini`（节 APP: SERVER/USERNAME/PASSWORD；节 VERIFY: PWD）
- `HttpReq.cs`：HTTP 全合约；`NetManager.cs`：WS 生命周期
- Model/ 17 个模型与安卓 jsonDecode 完全同构
- ViewModels：Login（立即登录）、Home、OnlineConfig、PreviewSetting、EditPwd

## 四、③ 游戏端 — 游戏端.exe（JavaFX + exe4j）

**技术**：exe4j 打包的 JavaFX 程序，自带 jre-9（32 位）
**泄露的完整依赖清单**（exe 字符串）：
`QueshengDaPai.jar`(主程序) + `MobileIMSDK4j.jar`(与安卓同一 IM 协议库) +
`MobileIMSDKServerX_META.jar` + `okhttp-3.9.1` + `ormlite-core/jdbc-5.0` +
`sqlite-jdbc-3.7.15` + `rxjava-2.2.3` + `gson-2.3.1` + `jintellitype-1.3.9`(全局热键)

**error.log 泄露**（运行时堆栈）：
- 包名 `quesheng`：MainApp / StageController / LoginController / util.ObjectKit
- 启动读取 `.\sconfig.config`（服务器地址等配置，缺失时报 FileNotFoundException）
- JavaFX FXML UI；MobileIMSDK 客户端 → 与服务器 18889 WS 同协议

**覆盖区**：8.97MB exe4j 专有压缩载荷（高熵，含 GB2312 压缩数据），jar 已打包其内；
未实现 exe4j 专有解包器，jar 内容未提取（诚实边界）。类名/依赖已从字符串完整恢复。

## 五、交叉比对结论

1. **三端同源**：PC 图传（.NET）与安卓（Flutter/Rust）与游戏端（Java/MobileIMSDK）
   实现同一套服务器协议——协议常量、端点、RSA 流程、dataKey、401/301 行为全部对齐。
2. **PC 图传 = 电脑摄像头/采集卡版的数据采集端**（与主板摄像头设备同角色）。
3. **游戏端 = 牌局展示端**（本地 sqlite 存牌局、全局热键、MobileIMSDK 实时收牌）。
4. fixture_server.py 可据 C# 源码进一步补齐 set_params_v2 等字段的精确校验行为。
