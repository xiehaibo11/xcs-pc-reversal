# 逆向③ 游戏端 — 游戏端.exe 逆向文档

样本：游戏端/游戏端.exe（9,517,056 字节 PE32 GUI 32位）+ 自带 jre-9（32位）+ error.log
打包方式：**exe4j**（.install4j/i4jruntime.jar、jar.pack 字符串实锤）

## 1. 程序角色

牌局展示端（桌面端）：以 MobileIMSDK4j 客户端身份连接服务器，实时接收
四方位主板识别的牌局数据并展示；本地 sqlite 存牌局；支持全局热键。

## 2. 泄露的完整依赖清单（exe 字符串，exe4j classpath 表）


## 3. error.log 还原的启动流程与类结构

```
quesheng.MainApp.start(MainApp.java:45)
 └ StageController.loadStage(StageController.java:85)
    └ FXMLLoader.load → quesheng.controller.LoginController.initialize(LoginController.java:109)
       └ util.ObjectKit.getObject(ObjectKit.java:24) → 读 .\sconfig.config
```

- 配置文件 `.\sconfig.config` 由 `ObjectKit.getObject` 读取
  （FileInputStream → Java 对象反序列化，即配置是**序列化的 Java 对象**，
  含服务器地址等；首次运行缺失属正常——界面手填后回写）
- UI 为 JavaFX FXML：LoginController 先于主界面加载
- 错误文本为 GB2312 乱码（"系统找不到指定的路径"），程序按 ANSI 编码写日志

## 4. 覆盖区（exe4j 载荷）

PE 段外覆盖区 8,978,432 字节（占 exe 总量 94%）。特征扫描：
无 PK/CAFEBABE/CAFED00D/gzip 明文头 → 载荷为 exe4j 专有压缩+可选加密格式。
含义：**QueshengDaPai.jar 与全部依赖以加密打包形式内嵌**，无法用通用工具直接解出。
已获得的信息（classpath 表、启动类、堆栈）足以还原架构；jar 字节码属诚实未决项。
（如需继续：可实现 exe4j 专有解包器，或在 Windows 上运行该程序后从其解包目录取 jar。）

## 5. 协议对照

游戏端用 MobileIMSDK4j —— 其协议与服务器 18889 端口的 types
1(心跳)/2(业务)/3(登出)/4(QoS回执)/6(登录)/50/51/52/54(被踢) 完全同源；
PC 端 Constant.cs 另有 **5(ECHO)/53(回显)** 两类型，安卓未出现 53。
MobileIMSDK 为公开开源库（MIT），协议细节可据其公开源码补充。

## 6. 与 PC 图传/安卓的关系

- 服务器视角：游戏端与 PC 图传同为"客户端"，但角色不同——
  PC 图传上传识别数据（zhuo/add），游戏端只收牌局展示（不下注不上传）
- 游戏端无 zhuo/* 调用证据（依赖里无业务 HTTP 封装，仅 okhttp 备用）
