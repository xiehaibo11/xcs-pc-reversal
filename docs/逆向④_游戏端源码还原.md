## 5. sconfig.config 精确结构（路线图 B3 闭合）

- 路径：工作目录 `./sconfig.config`（exe4j 置 CWD=exe 目录）；由 ObjectKit.getObject 以
  **ObjectInputStream** 反序列化，读取时强转 `quesheng.model.SystemConfig`（LoginController.initialize 第一行）；
  读取失败返回 null → new SystemConfig() 走首启用流程。写入用 ObjectKit.WriteObject。
- 类：`quesheng.model.SystemConfig implements Serializable`，
  **serialVersionUID = -6284005833985478852**
- 关键字段：
  - `Map<String,String> users`（LinkedHashMap）：**key=DES(用户名)、value=DES(密码)**（记住密码功能）
  - `String choseIp`：**DES(nihao985) 加密服务器 host/IP 后的大写 HEX**（首启用由用户在登录窗输入
    Base64(host)，程序 Base64 解码后 DES 加密存入；后续启动解密回显）。静态代码中 HTTP 调用方会再追加 `:8081`，不能将此字段简单设为 `IP:8081`；原环境真实配置样本待动态核对。
  - `Boolean isFirstLogin`：首启标志（true 时显示 IP 口令输入框）
- 其余 ~140 个 public 字段全部是玩法/UI 规则开关（int 0/1、String 热键名、double[] 背景色）：
  mapaicengshu(2)、wanjiapaishu(13)、tiaopai("隔跳")、meishouzhangshu(4)、yucepai(10)、
  wanjiarenshu(4)、huanshoupai、gangfa("轮到自由杠(手动杠花)")、ganghua("顺杠牌")、
  zidingyibeijingyanse[3]、热键 huoqushuju/guopai/xunhuanguopai/guodong/kanchupai/mopai("空格键")/
  chipai_kjj/gangpai/pangpai_kjj/chexiao("z")/shubiaoyouji("撤销")、leqing/guangxi152/xianmajiang/
  yuhuanwahua/wenchengmajiang/wenlingmajiang 等地方玩法分支（乐清/广西152/仙游/文成/温岭…）。
  **完整字段清单见 game-src/quesheng/model/SystemConfig.java（62 行声明段）**。
- 复刻配方（伪代码，需调用 Java setter 构造实例）：`SystemConfig cfg = new SystemConfig(); cfg.setChoseIp(DESKit.Encrypt("IP")); cfg.setIsFirstLogin(false); ObjectOutputStream.writeObject(cfg);`，DES/CBC/PKCS5 key=IV="nihao985"。不要重复写入端口；需在 fixture 验证后再作为运行配置。

## 6. 登录与连服务器逻辑（全链路）

```
首启用: 用户在登录窗输入 Base64("服务器IP") → DES 存 sconfig.choseIp（调用方自行追加 :8081）
登录窗: processLogin
  └ userLogging → POST http://<DES解密(choseIp)>:8081/api/login/login
      form: ajax=true, deviceid="", lastloginversion=v2.1.0, devicetype=3,
            password, username, loginfield=username, type=username, version=1.0.0.1
      resp: {success, message(→Gson→User), jwt}
  └ 成功 → goToMain → IMClientManager.initMobileIMSDK()
      appKey=5418023dfd98c579b6001741
      serverIP = User.server_ip（登录响应下发，可与 HTTP 服务器不同机）
      serverUDPPort = 7901
  └ 切 IndexView → MainController.onShown:
      doZhuoLoginImpl → LocalUDPDataSender.SendLoginDataAsync(
          loginUserId = "<user_id>_2",      ← _2 为该端设备标记
          password    = jwt,
          loginToken  = "<user_id>")
      openJiance → 每 10s（首延 5s）POST /api/yiZhuo/get
      OTA: POST /api/config/GetLastVersion (version=dapai64|dapai32) → 高版本则下载 exe
      默认密码检测: sha256(salt+"******")==password → 提示修改
```

### 6.2 zhuo/* 结论（**推翻路线图旧判断**）
逆向③曾判断"游戏端无 zhuo/* 调用"。反编译证实：**存在 `/api/yiZhuo/get` 消费端调用**——
- IM 收到 typeu==1 推送立即 jiance()，另有 10 秒兜底轮询；
- 响应 `list` 每项含 zhuo_id 字段，是识别端上传的桌面牌局；
- 方向为**只收不发**：无任何 zhuo/add/上传端点调用（上传方是 PC 图传）。
即旧结论"不下注不上传"正确，"无 zhuo 调用"应修正为"只调用 yiZhuo/get 拉取，不上传"。

## 7. 协议对照（与 PC 图传 Constant.cs）

MobileIMSDKServerX_META.jar 用 javap -constants 直接读出常量（开源库标准值）：

```
ProtocalType.C: LOGIN=0, KEEP_ALIVE=1, COMMON_DATA=2, LOGOUT=3, RECIVED=4, ECHO=5
ProtocalType.S: RESPONSE_LOGIN=50, RESPONSE_KEEP_ALIVE=51, RESPONSE_ERROR=52, RESPONSE_ECHO=53
ErrorCode.ForS: RESPONSE_FOR_UNLOGIN=301     ← ChatTransDataEventImpl.onErrorResponse 处理
ErrorCode.ForC: 201~205（断线/连接失败/未初始化/本地网络/未配置）
```

对照结论：
- PC Constant.cs 的 1(心跳)/2(业务)/3(登出)/4(QoS回执)/5(ECHO)、50/51/52/53、ERR 301
  与本库**逐一同源同值**（此前"5/53 安卓未出现"实为安卓端未用，库本身支持）；
- PC 端的 **6、54 两个类型不在本库**——属服务器/PC 端定制扩展（游戏端 SDK 不产生也不处理）；
- 游戏端业务推送用 **typeu=1**（用户自定义字段，非协议 type），服务器推"牌局有更新"信号。

## 8. 与 PC/安卓端交叉验证的新事实

1. 登录合约同族：`/api/login/login`，参数 ajax/deviceid/lastloginversion/devicetype/password/username/loginfield/type/version —— 与 PC 图传 22 端点合约同构；**游戏端 devicetype=3**（PC/安卓各为其值）。
2. 登录响应含 `server_ip` 下发 → 三端"服务器地址服务端下发"模式一致；游戏端 IM 端口 **7901**（图传服务端口 18889 之外的第二业务端口，或同机不同服务，待服务器侧验证）。
